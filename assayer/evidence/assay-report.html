What it is

An assayer takes a sample, tests it against a known standard, and certifies what it actually is. This is that, applied to whatever is being built — a site, a report, a pipeline, a page of docs.

Beat one

Anchor

Write down what “good” means in checkable terms, before building. A standard written afterwards just describes whatever you happened to produce.

Beat two

Build

The work itself. Owned file paths when agents run in parallel, so they stop overwriting each other.

Beat three

Prove

A fresh checker that never saw the build reasoning opens the artifact and uses it. A diff shows intent; only the artifact shows what was produced.

Sample 1 — where slop comes from

Two prompts, same model, same day, no guidance either time. The only variable was how much the brief actually said.

Slop is an information failure before it is a taste failure. It fills a vacuum. So the fix sits upstream: if the specifics can’t be named, that’s a blocker to raise, not a gap to design around.

The thin-brief page didn’t only look generic. It manufactured its proof, in shippable HTML, with nothing marking it as fictional.

The limit worth stating plainly. The checker is also an AI, and it shares the builder’s taste. Separation defeats self-review bias — it does nothing about shared priors. Across two independent passes the checkers found every measurable defect and not one aesthetic one. Those were all caught by the person reading the page.
